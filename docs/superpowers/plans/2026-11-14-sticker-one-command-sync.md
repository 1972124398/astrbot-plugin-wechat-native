# 一条私聊指令准备表情库

用户希望仅保留 `/表情包同步`，自动完成目录同步和所有已添加官方包的下载，减少往返操作。
继续现有实现和 HTTP API，通过 PR 合并；SPEC、CHANGELOG 与使用文档同步更新。

## 交互与实现

- 管理员私聊发送一次同步指令，先收到开始提示，插件等待目录同步完成，再逐个下载未就绪包。
- 已就绪包跳过；单包失败不阻断其他包，最终汇总下载成功、已就绪、失败及未完成数量和异常包 ID。
- 每个 Native 任务最多自动等待五分钟，超时保留任务编号，不声称完成；再次同步只核对原在途任务。
- 同一适配器仅运行一个完整同步流程。复用持久化幂等键、任务校验、关闭取消及只读重启恢复。
- 按包区分下载操作，兼容此前 `library:download` 在途记录，避免一条消息多个包互相覆盖或重复提交。
- 移除列表、单包下载、状态和帮助子指令。账号成员关系仍在手机微信中添加；Native HTTP 400 仍如实报告失败。
- Saved 由原有 `scope=all` 同步；本轮串联已添加官方包下载，不新增引用收藏、导出或自动购买。

## 步骤与验证

1. 先增加多包、跳过、异步轮询、部分失败、重复并发及旧任务兼容测试，确认现有实现失败。
2. 串联同步与下载，复用管理权限和任务状态；测试取消、权限撤销与超时不会导致再次提交。
3. 更新 SPEC v1.6、CHANGELOG、帮助与配置提示、README 和功能文档，发布版本为 v0.3.17。
4. 运行专项测试、Ruff、全量回归和独立审查，再通过 PR 合入主分支。

## 重点检查

- 同一条消息的多个包各有独立任务，下载回执严格匹配包 ID。
- 同步失败时不开始下载；一个下载失败后仍处理下一个包。
- 已知在途任务只 GET，未知受理结果不会 POST；旧版本在途下载同样受保护。
- 等待期间的关闭、撤回、权限或配置变化阻止后续提交。
- 超时和部分失败的回复不显示“全部完成”。
